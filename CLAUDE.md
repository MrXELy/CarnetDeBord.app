# CarnetDeBord.app

Webapp PWA pour un chauffeur routier : noter les étapes de ses trajets (début et fin de journée, chargement, livraison, carburant), ses lettres de voiture et voir le récap de sa semaine. Utilisée surtout sur téléphone, aussi sur PC. Thème sombre, sobre et moderne.

## Règles de travail

- **Réponds toujours en français.** L'utilisateur débute en développement : explique simplement.
- **Avant tout `git push`** : lance le serveur de test local, donne l'adresse pour tester (PC et téléphone), puis **demande l'accord**. Ne jamais pousser sans accord explicite.
- **Le dépôt GitHub est public** : aucune donnée personnelle dans les fichiers commités, tests compris (positions GPS réelles, lieux de base, noms de clients, immatriculations, nom de l'utilisateur). Dans les tests, utiliser des centres de villes publiques (Narbonne, Toulouse, Périgueux…) et des noms génériques.
- **Fuites vérifiées avec gitleaks** pour les secrets : avant chaque commit `gitleaks git --pre-commit --staged -v`, avant chaque push `gitleaks git --log-opts="origin/main..HEAD" -v`. Si gitleaks trouve quelque chose : ne pas commiter ni pousser, prévenir l'utilisateur. La clé publishable Supabase est ignorée via `.gitleaksignore` (normale, publique). gitleaks ne voit que les secrets : **relire aussi le diff** avant chaque commit pour les données personnelles (GPS, lieux, clients, immatriculations, nom).
- **Services publics gratuits** (itinéraires, recherche de villes, fonds de carte…) : **avant d'en utiliser un, se renseigner sur ses conditions d'utilisation** (nombre de demandes autorisé, usage permis, mention de la source, contact…), les respecter dans le code et les noter ici. Exemple : FOSSGIS (Valhalla) demande au plus une demande par seconde, la mention OpenStreetMap et une adresse de contact sur le site (pas d'adresse affichée : choix de l'utilisateur, pour ne mettre aucune donnée personnelle dans le dépôt public). Recherche de villes : Photon (komoot) demande un usage raisonnable (pas de chiffre, limité en cas d'abus) ; geo.api.gouv.fr, environ 50 demandes par seconde par adresse IP ; l'autocomplétion attend 300 ms après la frappe, très en dessous. Plan IGN (tuiles WMTS de la Géoplateforme) : pas de limite de demandes (CGU de cartes.gouv.fr), Licence Ouverte Etalab (mention de l'IGN sur la carte), seulement les tuiles affichées, jamais de préchargement.
- **Aucune clé secrète dans le code.** La clé Anthropic est seulement dans les secrets Supabase (`ANTHROPIC_API_KEY`). La clé publishable Supabase de `src/config.ts` est publique par conception.
- Style de code : Prettier avec `--single-quote --print-width 120`. Commentaires en français.

## Pile technique

React 19, Vite, TypeScript, vite-plugin-pwa, date-fns (locale fr), lucide-react, jsPDF (feuille de semaine, chargé à la demande), Leaflet (carte navigable de « Choisir l'itinéraire », chargée à la demande), Mediabunny (fabrication de la vidéo MP4 de la semaine rejouée, chargé à la demande), vitest. Données dans Supabase (tables `events`, `waybills`, `ocr_usage`, `week_maps`, `user_settings` avec RLS ; stockage privé `waybill-photos` ; fonction Edge `read-waybill` pour la lecture automatique des LV avec Claude). Inscriptions désactivées.

## Commandes

- `npm install` : installer les dépendances.
- `npx vite --host` : serveur de test **en https** (`@vitejs/plugin-basic-ssl`, certificat fait maison : la première fois, accepter l'avertissement du navigateur), accessible depuis le téléphone sur le même Wi-Fi (adresse en `/CarnetDeBord.app/`). Le https est nécessaire sur le téléphone : en http, `crypto.randomUUID` et le GPS sont bloqués (page noire sur « + »).
- `npm test` : tests (vitest). `npm run build` : vérification TypeScript et build.
- `gitleaks git -v` : chercher des secrets dans tout l'historique (installé avec `brew install gitleaks` sur macOS, `winget install Gitleaks.Gitleaks` sur Windows).
- Mode démo local : ajouter `?demo` à l'adresse (seulement en développement). Il lit `data/demo-events.json` et ne contacte pas Supabase ; `?demo=reset` recharge les données. Les changements faits en démo restent dans le navigateur (par adresse : localhost et 192.168… sont séparés) ; « Sauvegarder la démo » (Options, mode démo) télécharge étapes, LV et réglages (sans photos) au format `{ events, waybills, settings }`, à mettre à la place de `data/demo-events.json` (l'ancien format, la liste des étapes seule, est encore lu).
- Déployer la fonction Edge : `npx --yes supabase@2.121.0 functions deploy read-waybill --project-ref bjtqghlacclhbjjyarxj --use-api`.
- Les migrations SQL (`supabase/migrations/`) sont lancées à la main par l'utilisateur dans l'éditeur SQL de Supabase. Pas de migration 001 : `supabase/schema.sql` en tient lieu (installation neuve, il reprend aussi l'index de la 008) ; les migrations vont de 002 à 009. La 008 ajoute l'index `events (user_id, updated_at)` pour la synchro ; la 009 ajoute la colonne `week_sheet` (réglages de la feuille de semaine) à `user_settings`.
- Mise en ligne : chaque push sur `main` déploie sur GitHub Pages (https://mrxely.github.io/CarnetDeBord.app/) via GitHub Actions.

## Organisation

- `src/lib/sync.ts` : synchro hors ligne d'abord (cache localStorage, file d'envoi), `EventStore`.
  - Chaque `Collection` a un compteur `version` ; les listes `events` et `waybills` gardent le même tableau tant que rien ne change (les caches et les `useMemo` s'appuient dessus). **Tout code qui modifie `items` doit augmenter `version`.** `loadedAt` et `deliveredAt` utilisent un index mémorisé.
  - Une synchro demandée pendant une synchro en cours est relancée une seule fois à sa fin.
  - Si le lot d'envoi est refusé, les lignes repartent une par une (`isRowRefusal`) : la ligne refusée reste dans la file, l'erreur la nomme (`RowRefusedError`) et la synchro continue (réception, LV, photos, cartes, réglages) ; une LV qui pointe vers une étape refusée est refusée seule. Panne réseau, session expirée, colonne ou table absente : pas de renvoi ligne par ligne.
  - Le curseur de réception est `date|id` (un ancien curseur, la date seule, est encore lu).
- `src/lib/weekSheet.ts` : contenu de la feuille de semaine (calcul pur, testé) ; `src/lib/weekSheetPdf.ts` : son dessin en PDF (jsPDF, importé à la demande) ; `src/lib/share.ts` : partage ou téléchargement d'un fichier (PDF, images des cartes) ; le téléchargement est forcé (type `application/octet-stream`), jamais une ouverture dans un onglet. Firefox Android ne sait pas partager de fichiers (`navigator.share` : « Passing files is currently not supported ») : un PDF y finit en about:blank dans l'appli installée ; l'utilisateur installe donc l'appli avec Chrome.
- `src/lib/useSheet.ts` : fenêtres en panneau (reprend `useModal`) : fermeture animée (croix, fond, retour du téléphone, après enregistrement) et tirage du haut du panneau vers le bas pour fermer (`shouldDismiss`). `ref` sur `.modal-backdrop`, `handle` sur `.modal-header`, `close` à la place de `onClose`. `src/lib/signOut.ts` : déconnexion. `src/lib/useSwipe.ts` : glissement (semaine, statistiques) ; mode `global` pour l'accueil : geste écouté sur toute la page, ignoré si une fenêtre est ouverte, depuis un champ ou une bande qui défile de côté. `overscroll-behavior: none` (pas de retour ni de rafraîchissement de Firefox au glissement) et `touch-action: pan-y pinch-zoom` sur `.app`.
- `src/components/stats/` : morceaux de `StatsPage.tsx` (tuiles, sections, calendrier…). À n'importer que depuis `StatsPage.tsx`, pour rester dans le morceau chargé à la demande. Options, Recherche et page LV, comme les cartes et les Statistiques, sont chargées avec `lazy`.
- `src/lib/dates.ts` : la semaine commence le **dimanche à 22h**.
- `src/components/MapSvg.tsx` : dessin commun des cartes (fond IGN, villes repères, tracés, export PNG).
- `src/components/WeekMap.tsx` et `MonthMap.tsx` : cartes de la semaine et du mois ; `src/lib/weekMapGen.ts` calcule et enregistre les itinéraires d'une semaine.
- `src/lib/weekReplay.ts` : chronologie de la semaine rejouée (calcul pur, testé) ; `src/lib/replayCamera.ts` : caméra (calcul pur, testé) ; `src/lib/replayDraw.ts` : dessin d'une image de l'animation sur un canvas, fond de carte compris (contours en `Path2D`, net à tous les zooms) (sert à l'aperçu et servira à la vidéo) ; `src/components/WeekReplay.tsx` : fenêtre « Semaine rejouée » (chargée à la demande).

## Fonctions livrées

- **Étapes** : début et fin de journée, chargement, livraison, carburant (Doumen, AS24, DKV ; gasoil, AdBlue). Immatriculations reprises automatiquement ; le début de journée reprend le km de la fin de journée précédente. Lieu par GPS ou autocomplétion (Photon, geo.api.gouv.fr).
- **Vue semaine** avec récap des km, navigation par glissement, liste « Choisir une semaine » groupée par mois et saut à une date.
- **Lettres de voiture (LV)** : plusieurs par chargement, à compléter plus tard, choix des LV « dans le camion » à la livraison, page LV (glisser à gauche ou à droite change d'onglet : À compléter, Dans le camion, Toutes ; sans boucler). Un nouveau chargement reçoit d'office une LV vide (Scanner/Saisir la remplissent). La « Ville de chargement » et les dates de chargement et de livraison d'une LV sont celles de ses étapes : les modifier depuis la fiche change les étapes (`EventStore.setEventPlace`, `setEventTime`, `applyStepChanges` dans `src/lib/places.ts`), donc aussi leurs autres LV. Date de livraison seulement pour une LV livrée. Fiche LV en **lecture seule** à l'ouverture (texte simple, photos à regarder sans poubelle, champs vides cachés, n° « À compléter ») ; bouton « Modifier » pour la saisie ; nouvelle LV ou LV encore vide (`isBlankWaybill`) : saisie directe, avec un gros bouton « Scanner la lettre de voiture » à la place des photos tant qu'il n'y en a pas. Seule la première photo est lue automatiquement ; les suivantes (bons de livraison…) sont seulement ajoutées (« Lire la photo » à la demande, sur la dernière photo). Dans les fiches de chargement et de livraison, un œil à droite de chaque LV ouvre sa fiche (crayon si la LV est encore vide : elle s'ouvre en saisie) (plus de croix pour retirer : « Supprimer la lettre » dans la fiche, effectif à l'enregistrement de l'étape). Pastille en haut de la fiche LV identique d'où qu'on l'ouvre (page LV, chargement, livraison ; `waybillContext`) : « Chargée : lieu · date » puis à la ligne « Livrée : lieu · date » ou « À livrer » ; l'étape ouverte est prise telle qu'elle est saisie. Une LV sans étape de chargement (créée à la livraison) montre quand même ville et date de chargement : remplies, elles créent l'étape de chargement (sans km, plaques de la livraison ; `addLoadingStep`), enregistrée avec la livraison ou tout de suite depuis la page LV. Une nouvelle LV saisie à la livraison est livrée ici dès l'ouverture de sa fiche (date de livraison affichée). Choisir un chargement existant : pas encore fait.
- **Photos des LV et lecture automatique** par la fonction Edge `read-waybill`, **en direct** : une ligne sous la photo montre la dernière remarque ou information écrite par l'IA, bouton « Détails » (`ReadingDetails.tsx`) avec ses remarques, ce qu'elle a lu ou non, durée et coût, ou la raison de l'échec (`src/lib/liveReading.ts` lit la réponse inachevée). En mode démo, lecture simulée. Photos d'une LV supprimée, retirées d'une fiche ou prises dans une fiche fermée sans enregistrer : mises dans une corbeille locale (`trashPhotos`, `cdb.photo-trash`) vidée à chaque synchro. La file d'envoi des photos (IndexedDB) et la corbeille sont communes au navigateur : seules les photos de l'utilisateur connecté (chemin `<id>/…`) sont envoyées ou effacées, jamais celles du mode démo (`demo/…`) ou d'un autre compte. Ménage quotidien des photos orphelines de plus de 24 h (fonction SQL `orphan_waybill_photos`, migration `007_orphan_photos.sql`), et bouton « Nettoyer » dans les Options (photos de plus d’1 h, dit combien de plus récentes attendent).
- **Kilométrage en photo** : bouton appareil photo à côté du km ; la même fonction `read-waybill` (`kind: 'odometer'`, Haiku) lit l'écran du chrono (VDO DTCO à l'arrêt : « 123456.7km ») ou le compteur. Photo envoyée directement, non stockée, comptée dans les mêmes limites. Alerte si le km est inférieur au dernier relevé ou s'il y a plus de 2000 km d'écart.
- **Gasoil** : interrupteur « Plein complet » sur l'étape carburant (colonne `full_tank`, migration `005_full_tank.sql`), réglé d'office selon la station. Plein noté dans une ville de station Doumen (`DOUMEN_CITIES` dans `src/lib/fuel.ts`) : Doumen choisi d'office si aucune station ne l'est encore. Conso calculée d'un plein complet au suivant par tracteur, compléments compris (`src/lib/fuel.ts`) ; `fuelReport` donne pour une période le gasoil acheté et le gasoil consommé (km × conso de l'intervalle, ou conso habituelle des 4 derniers pleins si pas encore de plein). Affichée sur la carte du plein et dans les Options.
- **Cartes** de la semaine et du mois (accès au mois par « Carte du mois » dans la liste des semaines). Réglages retenus sur l'appareil : itinéraires ou lignes droites, « France entière » (sinon cadrée sur les trajets), villes, départements, et numéros des étapes (carte de la semaine).
- **Semaine rejouée** (bouton rond ▶ en bas à gauche de la carte de la semaine) : animation chronologique des trajets sur le fond sombre des cartes (France, départements, villes) : tracés qui se dessinent à la couleur du jour, camion (point blanc), lieux atteints, jour et heure en haut, km parcourus et étape en bas (« Chargement — Colomiers (31) », « Vers … », « Repos · 14 h 15 — Villeneuve-sur-Lot (47) » avec carte assombrie), barre d'avancement. **Pas de nom de client** (vidéo pour l'utilisateur seul). **Camion à vitesse constante à l'écran** (durée d'un trajet selon la longueur de son tracé, choix de l'utilisateur), arrêts 1,6 s et repos 2,6 s pour avoir le temps de lire (`STOP_SECONDS`, `REST_SECONDS`), réduits seulement s'ils dépassent 60 % de la durée choisie (un message donne alors la durée minimale pour tout lire) ; départ après une fin de journée ou trajet de plus de 12 h : repos puis trajet à 70 km/h. **Caméra** proche du camion (largeur de la vue réglable par un curseur, 100 à 1000 km, 280 par défaut, retenue sur l'appareil : `replayViewKm` ; au moins cette largeur, recule sur les longs trajets : elle couvre le trajet de ± 2,5 s autour de l'instant), lissée (moyenne en cloche sur ± 2,4 s), calculée d'après le moment de l'animation (même image en lecture, au curseur et en vidéo) ; **à la fin, dézoom de 2,5 s sur toute la semaine puis 2 s de pause** avec « 5 jours · 15 lieux » (`OUTRO_SECONDS` ajoutées à la durée choisie). Fond de carte redessiné à chaque image (villes repères selon le zoom). Itinéraires enregistrés par tronçon, sinon lignes droites. Format vertical (1080 × 1920) ou carré (1080 × 1080) et durée (15 à 120 s) au choix, retenus sur l'appareil (`replayFormat`, `replayDuration`). Lecture, pause, curseur pour avancer à la main. **Créer la vidéo** (`src/lib/replayVideo.ts`) : MP4 1080 px, 30 images/s, fabriqué image par image avec WebCodecs (Mediabunny, codec : le premier que le navigateur sait encoder, H.264 en général), plus vite que la lecture (35 s de vidéo en ~5 s sur un Mac), sans passer par un serveur ; avancement en %, Annuler ; puis bouton « Partager la vidéo (13 Mo) » (geste séparé : le partage doit suivre un toucher) : menu de partage sur téléphone, téléchargement sur PC (`shareFile`). Navigateur sans WebCodecs (Firefox Android) : message « ouvre l'appli avec Chrome ». Vidéo périmée si un réglage change.
- **Statistiques** (bouton graphique en haut, `StatsPage.tsx`, calculs dans `src/lib/stats.ts`) : Jour / Semaine / Mois / Année, flèches et glissement, titre à toucher pour aller à une date, bouton de retour à la période en cours ; gros km avec comparaison, tuiles (heures, moyenne par jour, chargements, livraisons, gasoil consommé, conso), barres des km (toucher une barre ouvre la période), sections repliables : gasoil (courbe des derniers pleins, par station, AdBlue), temps de travail, clients et lieux (chargeurs et destinataires comptés par nom, sans tenir compte de la ville, un nom qui contient un autre client connu comme mot entier est regroupé sous lui (`clientGrouper`, aucun nom de client dans le code) ; départements des chargements et livraisons, ou pays hors de France ; tonnage ; anciennes étapes sans LV : champ `client` de l'étape), calendrier du mois, records et km par tracteur. Vue Jour : étapes de la journée et repos avant. Page laissée ouverte : « maintenant » rafraîchi au passage d'une limite de période, au retour sur la page, ou toutes les 10 min au plus (`nowIsStale`).
- **Km à vide** (`src/lib/emptyKm.ts`) : « dont X km à vide · Y % » sous le gros km (toutes les vues), section « Km à vide » (semaine, mois, année : barre en charge / à vide, part comparée à la période d'avant, nombre de trajets à vide et moyenne, le plus long qui ouvre son jour, détail par tracteur s'il y en a plusieurs, trajets incomplets signalés) et part à vide en gris dans les barres des km. Calcul mémorisé dans `EventStore.kmTimeline()`.
- **Recherche globale** (loupe en haut, `SearchPage.tsx`, `src/lib/search.ts`) : dans toutes les étapes et leurs LV (ville, département, client, chargeur, destinataire, n° de LV, marchandise, notes, station, plaque avec ou sans tirets, km, type d'étape), sans accents ni majuscules, tous les mots doivent se retrouver. Résultats groupés par jour, les plus récents en premier (100 au plus) ; toucher une étape ferme la recherche et l'affiche dans sa semaine (défilement jusqu'à elle et brève lueur) ; la dernière recherche est gardée à la réouverture.
- **Frais de déplacement** (`src/lib/allowances.ts`) : pastille des frais sous la semaine (icône et montant seulement, à côté de la pastille de la carte, icône seule ; ainsi les pastilles tiennent sur une ligne) (détail dans `AllowancesSheet.tsx`), tuile et section « Frais de route » dans les Statistiques (semaine, mois, année ; pas par jour). Bases et tarifs (avec date d'effet) dans les Options, enregistrés dans la table `user_settings` (migration `006_user_settings.sql`, une ligne par utilisateur, id = son identifiant), jamais dans le code.
- **Déconnexion** (`src/lib/signOut.ts`, bouton en bas des Options) : envoie d'abord ce qui attend, avertit s'il reste des envois ou des photos non envoyés (perte à confirmer), puis efface les clés `cdb.<id>.*` et les photos de l'utilisateur, seulement si la session est vraiment fermée (sinon message et rechargement). Bouton occupé (« Envoi en cours… », « Déconnexion… »), une seule déconnexion à la fois, envoi limité à 20 s (`SEND_TIMEOUT_MS`) : au-delà, même avertissement de perte que pour un échec. Les réglages de l'appareil (`cdb.settings`) sont gardés.
- **Feuille de semaine en PDF** (pastille à icône de document sous la semaine, à côté des pastilles des frais et de la carte) : la feuille papier de l'entreprise (A3 pliée) redessinée, cadre bordeaux et données en bleu, 3 pages : page 1 en A4 (conducteur, tracteur, agence, semaine n° du lundi au samedi, départ de chaque jour : lieu et km du premier début de journée, départ du dimanche soir sur la ligne Dimanche), intérieur en A3 paysage (chargements et livraisons), page 4 en A4 paysage (carburant). Partagée sur téléphone, téléchargée sur PC. Nom du conducteur, agence et 5 colonnes « Dépôts » (titre + villes des pleins) dans les Options (`user_settings.week_sheet`, migration 009), jamais dans le code.
- **Options** : mode Europe pour la recherche de villes, exports CSV (étapes et LV), compteur des lectures automatiques du mois ; tout en bas, la version : commit et heure de construction (`__BUILD_COMMIT__`, `__BUILD_DATE__` posés par `define` dans `vite.config.ts`, « · test local » sur le serveur de test).

## Choix déjà faits (ne pas reproposer sans raison nouvelle)

- **Chronologie Google abandonnée** (vrais trajets GPS) : pas d'API, export manuel seulement, recalage OSRM peu fiable. L'utilisateur a choisi de faire sans.
- **Itinéraires** : Valhalla public (FOSSGIS, `valhalla1.openstreetmap.de`), profil voiture (choisi par l’utilisateur : on compare aux km réels, le profil camion n’apporte rien), OSRM public en secours ; calculés **une seule fois** sur demande puis enregistrés (`week_maps`, un tracé par jour), simplifiés à quelques Ko ; bouton « Régénérer » toujours proposé (mis en avant si les étapes ont changé, discret sinon). Calcul **tronçon par tronçon** (d'un lieu au suivant) : Valhalla propose jusqu'à 3 itinéraires, on garde celui dont la longueur est la plus proche des **km relevés au compteur** (même tracteur, écart de 1 à 2000 km), sinon le plus rapide (`stopSegments`, `closestRoute` dans `src/lib/weekStops.ts`). Le serveur public d'OSRM ne propose jamais d'autre itinéraire. Conditions de FOSSGIS respectées : **une demande par seconde au plus** par serveur (`politeFetch` dans `src/lib/route.ts`, 1,1 s d'écart, une semaine d'environ 20 tronçons prend donc une vingtaine de secondes) et attribution OpenStreetMap avec lien « signaler une erreur » sous les cartes (`MapCredits`). Un itinéraire enregistré par tronçon (`MapLeg` : `key`, `km`, `manual` ; anciennes cartes : un tracé par jour, sans `key`), mis bout à bout par jour pour le dessin (`joinDayLegs`). **Choisir l'itinéraire** (`RouteChoiceSheet.tsx`, chargée à la demande) : dans la liste de la carte de la semaine, entre deux lieux qui se suivent, bouton « Itinéraire : X km · compteur Y km » (cachés au départ : lien « Choix d’itinéraire » / « Cacher le choix d’itinéraire » sous « Régénérer », réglage retenu sur l'appareil : `mapRouteButtons`) ; la fenêtre redemande les itinéraires du tronçon, les dessine en couleurs, avec durée, écart au compteur, « conseillé » (le plus proche du compteur) et « ACTUEL » ; le choix est enregistré (`withChosenRoute`, `manual: true`) et gardé à la régénération sans nouveau calcul. **« Passer par une ville… »** (dans la même fenêtre, `routeVia` dans `src/lib/route.ts`) : ville choisie avec l'autocomplétion (sans GPS), deux itinéraires ajoutés à la liste, « par le centre de X » (rue la plus proche du centre de la commune) et « par la grande route près de X » (voie rapide ou nationale la plus proche, `search_filter: min_road_class trunk` ; montré seulement s'il diffère du premier), le plus proche du compteur sélectionné d'office ; « Ajouter une autre ville » pour plusieurs villes dans l'ordre (retirables). Valhalla ne propose pas d'autres itinéraires avec une ville de passage. Le texte (« par le centre de Gaillac ») est gardé avec le tronçon (`MapLeg.via`) et affiché sur son bouton ; un itinéraire enregistré absent des propositions reste en tête de liste (« ACTUEL »). Choix validé avec l'utilisateur après essais : par le centre ajoute la traversée de la ville, la grande route se raccroche parfois à une autre route ; le compteur tranche. **Placer un point** (bouton rond à icône de pin posé en bas à droite de la carte, orange avec une croix pour annuler pendant le placement ; puis toucher la carte ; pas d'appui long : choix de l'utilisateur ; « Passer par une ville… » reste sous la carte) : point de passage pris tel quel, rayon de recherche de la route selon le zoom (`tapRadius`, 20 pixels, 15 à 300 m : sans rayon, Valhalla peut prendre l'autre sens d'une autoroute et imposer un demi-tour), nommé d'après sa commune (`communeAt`, geo.api.gouv.fr : « par un point près de Souillac »), déplaçable au doigt (recalcul au lâcher), sans recadrage de la carte. Villes et points se cumulent, **rangés du départ vers l'arrivée** (`orderWaypoints`), le choix dans la liste est retenu par clé. **Points de passage enregistrés avec l'itinéraire choisi** (`MapLeg.waypoints`) : à la réouverture, ils reviennent sur la carte et dans « Passage par », modifiables (déplacer, retirer, ajouter) ; l'itinéraire enregistré reste sélectionné (« ACTUEL ») tant qu'on ne touche à rien, sans doublon si le nouveau calcul retombe dessus. Choisir un itinéraire proposé efface les points. **Carte navigable** dans cette fenêtre seulement (`RouteMap.tsx`, Leaflet) : zoom, déplacement, toucher un tracé le choisit ; fond **Plan IGN** (Géoplateforme, tuiles WMTS `data.geopf.fr`, sans clé, gardé clair malgré le thème sombre : choix de l'utilisateur) ; les cartes de la semaine et du mois restent en SVG. Les étapes sans GPS sont placées au centre de leur ville. Lignes droites au choix.
- **Carte du mois** : un mois = les semaines rangées sous ce mois dans la liste (mois de leur **lundi**), entières ; elle réutilise les cartes des semaines. Une couleur par semaine, points sans numéro, pas de flèches.
- **Numéros masqués** (carte de la semaine) : un petit point par étape, sans regroupement des lieux proches ; la liste sous la carte garde les numéros. **France entière** : toute la métropole, agrandie si un trajet en sort. **Enregistrer l’image** : bouton rond à icône posé en bas à droite de la carte ; seul « Générer / Régénérer » reste sous la carte.
- **Lecture des LV** : Claude Haiku par défaut (peu cher), bouton « Relire en mode fiable » avec Opus. Limites côté serveur : 2 lectures par photo, 30 par jour, 300 par mois. Alias de chargeurs (ETEX → Siniat). L'IA écrit d'abord de courtes remarques (`remarks`) pour le chauffeur, puis les informations ; on n'affiche pas son raisonnement interne. Lecture en direct pour les LV seulement (`stream: true`, une ligne JSON par message) ; le kilométrage reste en une fois. L'appli accepte encore l'ancienne réponse en une fois. **Marchandise** : l'IA recopie une ligne unique, ou résume plusieurs lignes en une ligne courte (total par unité + nature générale, 80 caractères au plus) ; l'utilisateur garde ce résumé, même avec le champ plus grand.
- **Kilométrage automatique** : le Bluetooth du chrono (DTCO 4.1, interface ITS) demanderait une appli native et rien ne garantit qu'il donne le km ; on lit une photo de l'écran du chrono à la place. Fichier `.ddd` de la carte conducteur : piste possible plus tard pour vérifier les km.
- **Consommation** : jamais litres ÷ km d'une même semaine (compléments de 200-300 L, semaines sans plein). **Doumen = toujours plein complet**, AS24 et DKV = compléments (modifiable à la saisie ; anciennes étapes sans `full_tank` déduites de la station). Intervalle écarté si km ou litres manquants ou conso hors 15–50 L/100.
- **Statistiques** : mêmes règles que le reste (semaine au dimanche 22h ; mois et année = semaines entières dont le lundi y tombe). Comparaison avec la période d'avant **coupée au même moment** si la période est en cours. Km d'une période = somme des **tronçons** entre deux relevés qui se suivent avec le même tracteur, dont les deux relevés sont dans la période ; pas comptés : le repos (fin de journée → début suivant), un changement de tracteur sans relevé, les relevés incohérents (km qui baisse, saut de plus de 2000 km). Plaques comparées sans tirets ni espaces (`plateKey`), partout (km, conso, alerte de km). Pas de badges pour l'instant.
- **Km à vide** (validé avec l'utilisateur) : de la **dernière livraison au chargement suivant**, retour à la maison et trajet du matin jusqu'au premier chargement compris ; chargement le vendredi et livraison le lundi = en charge. Livraison suivie d'une livraison = en charge. Une LV chargée avant et livrée après la livraison = pas à vide ; après la dernière livraison notée, à vide sauf s'il reste une LV dans le camion (une LV oubliée ne bloque pas un trajet terminé). Même calcul par tronçons que les km : jamais de soustraction entre deux compteurs ; partie inconnue non comptée et trajet signalé « incomplet ». Avant la première opération ou si une étape sans km change l'état en route : état inconnu, non compté. Part = à vide ÷ (à vide + en charge). Un trajet compte (nombre, moyenne, plus long) dans la période de son chargement.
- **Frais de déplacement** (règles validées sur les vraies semaines avec l'utilisateur) : calcul par journée de travail d'après l'heure et le lieu des **débuts et fins de journée** seulement. Fin hors des bases → GD 2 repas + découcher si la journée couvre 11h45–14h15, sinon GD 1 repas. Fin à une base → repas midi (11h45–14h15) et soir (18h45–21h15). Casse-croûte : départ strictement avant 5h **et pas de découcher la veille** (sinon compris dans le GD). Repas unique de nuit : 4 h entre 22h et 7h, sans casse-croûte ni découcher la veille. Prime départ lundi : dimanche ≥ 22h ou lundi < 2h. Jour sans étape après un découcher (bloqué), compté quand la reprise est notée : GD 2 repas ; + prime bloqué le dimanche et les jours fériés (pas le samedi). Tarif étranger si la fin (GD) ou une étape du jour (repas) est hors de France. Tarifs de l'entreprise au 1er janvier 2026 par défaut ; prime bloqué à saisir. Pas de correction à la main pour l'instant.
- **Feuille de semaine** (règles validées avec l'utilisateur sur ses semaines) : pages 2-3, chaque chargement et chaque livraison est noté **au jour où il a lieu**, le jour écrit une seule fois. Un chargement ouvre une ligne (remorque, expéditeur, ville « Narbonne 11 », km, nature, poids, n° de LV) ; une livraison va sur la ligne de son chargement **du même jour** (par les LV, ou le dernier chargement du jour pour les anciennes étapes sans LV), sinon sur sa propre ligne avec la remorque, sans expéditeur (chargement d'un autre jour ou de la semaine d'avant : la livraison est quand même notée). Les livraisons suivantes d'une même ligne vont dessous, sans remorque. **Une ligne par LV** : un chargement de 2 LV prend 2 lignes (remorque, expéditeur, ville et km sur la première seulement), chacune avec la nature, le poids et le n° de sa LV ; une livraison du jour même va sur la ligne de sa LV ; une livraison d'un autre jour répète la nature, le poids et le n° de ses LV, une ligne par LV (remorque et destinataire sur la première). Un chargement non livré dans la semaine reste sans destinataire. Pas de « retours au dépôt ». Page 4 : départ = premier début de journée, arrivée et km de fin = dernière fin de journée, total km = fin − début ; un plein AS24 va en « AS 24 », DKV en « DKV » (à la place de « Shell »), les autres dans le dépôt de leur ville, sinon « Divers » ; croix « Plein OUI/NON » d'après « Plein complet » ; total des prises (gasoil seul). **Consommation jamais remplie.** Pas de logo.
- **Mode démo** (`?demo`) uniquement en développement, sans aucun appel à Supabase.
- **Thème sombre**, icônes sobres (lucide), boutons de type petits et de même taille, débuts et fins de journée discrets.
- **Style « verre + frise »** (choisi sur maquettes) : fond très sombre avec halos de couleur qui dérivent, cartes translucides, frise verticale avec un point de couleur par étape (rond creux pour début et fin de journée), police **Manrope** (paquet npm, gardée hors ligne), gros km de la semaine en dégradé. Animations douces (fenêtres qui montent du bas, étapes en fondu, glissement de semaine), coupées si le téléphone demande de réduire les animations. **Ordre inchangé : le plus récent en premier.** Fenêtres en panneaux de verre qui montent du bas (formulaires, LV, Options, semaines, cartes), redescendent à la fermeture et se ferment en tirant leur haut vers le bas ; types d'étape en 3 colonnes à la couleur du type ; étiquette « LU » sur les champs de LV remplis par la lecture (verte, orange si l'IA n'est pas sûre : liste `uncertain` de sa réponse, aussi marquée « pas sûr » dans les Détails) ; état coloré des LV dans leur page ; barre des lectures du mois dans les Options. Pas de bande bleue sur les plaques. **Barre du haut** : nom, pastille de synchro (vert à jour, orange en attente ou hors ligne avec le nombre, rouge erreur : toucher pour réessayer), puis Rechercher, LV, Statistiques, Options ; « Se déconnecter » est en bas des Options.
